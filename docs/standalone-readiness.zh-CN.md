# 独立运行状态与已知限制

本文说明当前 Go Core 哪些能力已经有实现和验证，哪些仍有明确限制。它不是对所有平台和所有任务的绝对安全或发布保证。

## 判断口径

- **已实现**：Go 代码中存在对应功能。
- **已验证**：测试或运行证据覆盖了相同代码路径。
- **部分实现**：有功能，但缺少重要路径或平台支持。
- **未实现**：当前 Go main 没有对应生产能力。
- **证据不足**：代码可能存在，但没有足够运行证据。

## 主要限制

1. **Shell 回滚**：任意 Shell 命令造成的外部副作用不能保证整次 Run 回滚。
2. **Worktree 隔离**：可以使用，但不是每次 Agent Run 都强制启用。
3. **浏览器和视觉**：依赖外部集成，不是内置浏览器 Runtime。
4. **TUI**：不是完整 IDE，编辑器级交互仍有差距。
5. **模型效果**：不同 Provider 和模型的长期表现不能由 Runtime 测试证明。
6. **Governor**：当前 Go main 主要提供只读 Analyze / Plan / Validate，不宣称自动执行全部认知治理。
7. **物理存储分层**：冷热元数据不代表已经有独立物理存储和自动垃圾回收。
8. **Linux / Desktop**：真实 DAP Adapter、cgroup/UID Broker 和原生 Wails 交互需要各自的平台验收。
9. **扩展 Cognitive Core**：未合并候选中的 Scope/Time/Evidence 和 Experience 能力不能算作 main 已有能力。

## 版本要求

任何能力声明都要对应准确的 Core Commit/Tag 和 Desktop 依赖版本。不要把历史测试、候选分支或交叉编译结果写成当前平台完整通过。
