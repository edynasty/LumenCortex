# 安全与信任

本文说明 Agent 能访问哪些数据、能执行哪些操作，以及 Core 如何防止项目配置、工具调用和进程越权。

## 工作区信任

项目目录中的配置文件属于不可信输入，只有工作区被用户明确加入信任列表后才会生效。信任状态会在启动 Run 和列出工具时重新检查。

撤销工作区信任后，项目 MCP 工具不再对新的 Run 可见，也不能继续调用。全局用户配置由用户管理，不受项目工作区信任开关控制。

## 工具权限

工具权限分为：

- **read**：读取信息。
- **write**：修改工作区文件。
- **exec**：执行命令或具有执行副作用的操作。

实际可用权限还受当前 Run 的策略、Host 配置、工具声明和人工批准约束。模型不能自行修改权限，也不能通过 MCP 参数把只读工具变成写入工具。

## MCP 信任

MCP Server 可以来自全局配置或项目配置。项目配置只有在工作区可信时才生效。

凭据通过环境变量引用提供，不把密钥明文写入持久化配置。工具的有效权限由 Server 声明和 Host 覆盖规则共同决定。

## 文件和路径保护

文件工具只能访问允许的工作区路径。路径穿越、符号链接逃逸、受保护状态目录和未授权目标必须在写入前检查。

批量编辑先验证所有目标，再执行原子批次，不能前几个文件已写入后才发现后面的路径越权。

## 进程和沙箱

Shell、Eval、DAP 和外部 Hook 使用受管理的进程生命周期。Host 决定可执行文件、环境、工作目录、超时和资源限制。

平台隔离能力不同。macOS Seatbelt、Linux cgroup/bwrap 和 Windows 能力不能互相替代；没有实际验证的平台必须标记为未验证。

## 不能作出的安全承诺

- 工具权限不代表任意 Shell 副作用都能回滚。
- Worktree 可用不代表每次 Run 都强制隔离。
- 通过容器测试不代表 Linux 主机隔离已验收。
- MCP 接入不代表所有外部服务都可信。
- 测试通过只证明覆盖到的边界，不代表系统绝对安全。
