# ADR-0002：Runtime 内存必须有明确上限

## 背景
长任务会积累大量消息、工具输出和知识图。若全部保留在进程内存，RSS 会随任务时间增长。

## 决策
1. 完整 Session 历史放磁盘，活动历史分页且有上限。
2. 工具输出采用流式处理，只保留有界头尾片段和元数据；完整内容进入 Artifact。
3. 知识图和搜索索引留在磁盘，只加载检索候选和当前活动子图。
4. 长任务状态主要增长在持久化存储，不应无限堆积在 Go slice/map。

## 实现原理
使用 SQLite/磁盘索引保存长期数据；查询限制候选数量；工具输出流式读写；每次模型请求构造有界 Working Set。

## 验收重点
测试长 Session、大工具输出、大知识图和长时间运行，确认内存增长受控。不能只测短任务。
