# Runtime Event 事件约定

Runtime Event 用来记录 Agent 执行过程中的生命周期信息，供 Desktop、插件和 Host 查看。事件是观察记录，不是权限凭证，也不能单独证明 Workflow 已完成。

## 事件字段

事件包含 ID、进程内实时序号、Session/Run 内递增序号、数据库持久化游标、UTC 时间和数据内容。Run、Parent、Worker、Task、Phase 等字段用于标识事件属于哪次执行。

## 两种保存方式

- **durable**：先写入现有 Session SQLite，再通知实时订阅者。持久化内容只保留必要元数据，不复制完整工具输入输出。
- **live**：保存在有界内存队列中。读取者太慢时会丢弃较早通知，并通过计数器记录丢失数量。实时流不是完整历史。

如果持久化失败，Runtime 会记录失败、取消受影响的执行，并拒绝继续声称历史完整。

## 查询和恢复

查询必须指定 Session，可按 Run、Worker、Task、事件类型、文本和游标过滤。订阅后应再查询历史，并按事件 ID/游标去重。

历史记录有数量上限。游标早于保留范围时会返回过期错误，需要重新获取快照。

## 安全和权限

Core 是权威事件写入方。Desktop 和插件不能追加权威事件。收到事件不能因此获得工具权限、把任务标为完成或满足验证条件。

删除 Session 时，关联事件按现有删除流程清理。实时事件和历史查询都必须检查 Session 权限及来源隔离。
