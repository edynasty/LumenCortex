# Agent 执行调试器

这个调试器控制的是 Agent 自己的执行过程，不是 Agent 正在开发的程序。调试目标程序请看 [DAP 程序调试](dap-debugger.zh-CN.md)。

## 能做什么

Host 可以在启动时设置断点，也可以在运行中查看当前 Run、执行版本、安全暂停位置和断点。

控制命令包括：

- `pause`：在下一个安全位置暂停。
- `continue`：继续执行。
- `step_agent`：前进一个可观察的 Agent 执行步骤。
- `step_model`：执行一次模型请求和响应。
- `step_tool`：执行一个工具并保存结果后暂停。
- `step_turn`：执行完当前轮，在下一次模型请求前暂停。
- `breakpoints`：查看或替换断点。
- `cancel`：取消原 Run。
- `close`：关闭调试控制器。

控制请求必须带 Session、Run 和当前版本号。过期控制不会误作用于后来的一次暂停或新 Run。

## 暂停和单步的边界

暂停发生在安全执行边界，不会冻结操作系统线程或强行挂起 Shell、MCP、Eval 进程。正在执行的操作会按自己的超时和取消规则完成或取消。

工具结果会先持久化，再进入暂停状态，避免恢复时重复执行已经完成的工具。

断点条件只支持明确的事件和状态匹配，不执行任意代码，也不会读取模型私有推理内容。

## 安全边界

每次暂停前后和每次 Host 控制请求都会重新检查 Session、来源隔离和存储状态。工具权限、Workflow、生命周期 Hook 和执行来源仍然有效。调试器不能替换工具参数、伪造验证结果或扩大权限。

断点、快照和活动控制器不是可恢复的持久化执行状态。Core 重启后必须正常启动新 Run。

Desktop 负责显示状态和转发命令；是否允许执行由 Core 决定。
