# Attention Light：检索和上下文选择

Attention Light 用于从项目知识和代码索引中找到与当前任务相关的信息，并控制送入模型的上下文规模。

它不是完整的人类注意力模型，也不能单凭检索分数判断一条知识是否正确。

## 处理过程

1. 根据当前任务生成查询。
2. 从持久化文本索引和符号索引中找候选。
3. 根据节点关系扩展有限范围。
4. 对候选排序并去重。
5. 按预算选择上下文。
6. 保留来源和节点身份，供后续验证。

## 当前 Go 能力

Go 实现包含词面/符号检索和有限图传播，并通过候选数量和上下文预算控制成本。

历史 Node 参考实现研究过 FTS、Embedding、PPR、RRF 和 MMR 等算法，但这些不能算作 Go main 的生产能力。

## 重要限制

- 文字相似不代表任务相关。
- 被检索到不代表事实正确。
- 排名靠前不代表证据更强。
- 上下文预算截断不能丢失验证所需的关键来源。
- 目前不能宣称已经具备完整的语义注意力或证据覆盖判断。

性能数据只适用于对应的测试数据和运行环境，不是固定延迟保证。
