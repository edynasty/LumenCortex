# Agent 执行流程

本文说明一次 Agent Run 从启动到结束会发生什么。

## 1. 启动

Host 提供任务目标、Session、模型配置、权限策略、工作区和可选 Workflow/交付合同。Core 检查配置、Session 状态和执行权限。

## 2. 准备上下文

Core 读取当前任务状态，检索相关 Notes、代码索引和知识图内容，按上下文预算选择信息。历史记录保存在数据库，但不会全部发送给模型。

## 3. 请求模型

模型根据任务和当前上下文生成回答或工具调用。模型提出的事实、经验和计划都只是候选，不会自动成为已验证知识。

## 4. 执行工具

每次工具调用都经过权限检查。文件修改还要检查路径和版本；Shell、Eval、DAP、MCP 和子任务由各自的受管理生命周期控制。

工具执行结果会写入 Session。失败、取消和超时必须保留真实结果，不能伪装成功。

## 5. 更新上下文

工作区发生变化后，Core 更新相应索引。下一轮请求使用新的上下文和工具观察结果。

## 6. 结束或中断

Run 可以正常完成，也可以因取消、Deadline、步数上限、预算、Provider、存储或 Workflow Gate 而中断/失败。终态和原因一起持久化。

## 7. 独立交付检查

如果 Host 提供交付合同，Agent 执行结束后 Core 独立核对文件、分支或提交要求。执行完成和交付验证是两个不同结果。

## 关键规则

- 工具结果先持久化，再允许后续步骤依赖它。
- 取消不能让旧请求影响新的 Run。
- 任务未满足必要检查时不能声明交付完成。
- 任何验证只能证明它实际检查的范围。
