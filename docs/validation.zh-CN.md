# 验证与测试证据

本文说明如何区分代码实现、机制测试和实际运行证据。

## 验证层次

1. **Build**：代码能否编译。
2. **Vet / 静态检查**：是否发现常见代码问题。
3. **Unit Test**：指定函数和状态变化是否符合预期。
4. **Integration Test**：多个组件组合后是否按预期工作。
5. **Race Test**：并发访问是否出现数据竞争。
6. **Runtime Test**：在指定操作系统、架构和环境中实际运行。
7. **Independent Review**：未参与实现的人检查源码、反例和证据。

这些层次不能互相替代。交叉编译不能证明原生运行；测试通过不能证明未覆盖的行为；实施方自测不能冒充独立复审。

## 报告必须包含

- 准确 Commit 和源码哈希；
- OS、架构和工具链版本；
- 完整执行命令；
- 开始/结束时间和退出码；
- PASS、FAIL、SKIP 分开统计；
- 原始日志；
- 失败原因和修复提交；
- 哪些历史结果因源码完全一致而复用。

## 证据边界

SKIP 不计入 PASS。被中断的命令不算通过。环境失败与产品失败必须分开。真实模型收益、经验迁移和长期认知演化不能仅凭单元测试得出结论。
