### A1 — I14 not enforced (P2, fixed)

- Invariant (design §4.5, handoff "Decision log"): every step's `modelRef` must equal `candidates[0]`, or the target of a logged failover. G2 requires the I14 test to be green.
- Evidence:
  - `agent.VerifyStep` existed but no test called it (grep: definition only).
  - Runtime tests replayed each decision on its own (`replayAll`) and compared rule names. They never checked that the answering model is reachable from those decisions.
  - Mutation: deleting VerifyStep's origin check (M24) or its final `modelRef` check (M25) **survived** the whole suite.
  - `VerifyStep` also accepted:
    - a failover entry whose candidate list differed from the step's logged `model.candidates` list, which let an unlogged model be reported as reached by a logged move;
    - a candidate list computed from a different session model than the Start's `model` decision resolved.
- Fix: `internal/agent/policy.go` `VerifyStep`.
  - Each failover must move within the candidate list the step logged.
  - When the record carries the Start's model decision, the candidate list must start from the resolved model.
  - The existing origin and final-model checks are kept.
- Regression tests:
  - `internal/agent/policy_test.go` `TestVerifyStepEnforcesTheI14Trace`: 11 cases, 4 positive and 7 forged.
  - `runtime/models_test.go` `verifyTrace`: `VerifyStep` over every persisted `agent_steps` row in the pinning, availability-failover, child and capacity-failover tests.
  - `internal/agent/loop_test.go` `TestLoopFailoverTraceAcrossStepsAndHealth`: two-step run, real loop.
- Failing before: the new tests were copied onto `09d83f8` in the scratch worktree, with production code unchanged. Two cases fail there: "failover over an unlogged candidate list" and "candidates from a model the Start did not resolve". With the fix, all pass.

### A2 — health Retry-After and success-clearing untested (P2, fixed)

- Mutation evidence:
  - M03 replaced `Health.Fail(ref, retryAfter(err))` with `Fail(ref, 0)` and **survived**. The runtime test checks only "unavailable now", which the 30 s default also satisfies.
  - M05 deleted `Health.Success` in `send` and **survived**.
- Regression: `TestLoopFailoverTraceAcrossStepsAndHealth` drives the real loop with an injected clock and checks that:
  - a model is still out at 31 min for `RetryAfter: 1h`, and back at 61 min;
  - step 2's `model.candidates` input records the failed model as `unavailable` and leaves it out;
  - a success on a model marked unavailable (advisory path) clears the mark.
- After the fix, M03, M05, M24 and M25 are killed, and so are two new mutants that remove each added VerifyStep check (M29, M30).

The implementation report also made three implementation choices that the handoff does not settle. Each should be confirmed by the owner:

- an unhealthy window of 30 s when there is no Retry-After (this matches design §4.5, so it is not new);
- a non-tool failover model is logged but gets no client;
- an unknown failover model, or one with an unset key variable, fails Start. This is stricter than "fail at first outage"; it follows D7.

## 6. Migration verification

- `0002_model_ref.sql` is byte-identical to `verify/sql/0002_model_ref.sql` (`diff`).
- Cross-binary probe with the baseline and HEAD `lcx-go` and isolated `HOME`/`XDG_*`:
  1. The baseline creates a v1 database with a session.
  2. HEAD opens it, migrates to 2, and writes backup `lumencortex.db.v1.<ts>`. `model_ref` is NULL; `integrity_check` returns ok.
  3. The baseline then refuses v2: `schema is newer … have 2, knows 1`.
  4. CHECK rejects `/x`, `p/`, `pm` and `a/b/c`, and accepts `p/m`.
  5. `db downgrade --to 0` is refused, the version stays 2, and no new backup is made.
  6. `--to 1` drops the column, `integrity_check` returns ok, and the baseline opens the database again.
  7. HEAD re-upgrades, and `model_ref` is NULL again.
- Locking and authority: `internal/migrate/model_ref_test.go` covers concurrent Opens and rollback/recovery when 0002 fails. These tests pass under `-race`.
- Existing session: its first Start writes `model.default` in the Start transaction. A later change of the default leaves it alone (CLI probe: default moved a→b, `resume` stayed on `p/a`, wire `model: up-a`).

## 7. Model policy and failover verification

- Precedence `model.user` > `model.session` > `model.default`, and the write rules: covered by tests. Mutants M08 and M22 are killed. M26 (always write the pin) is an equivalent mutant, because under `model.session` the written value equals the stored one.
- Pinning: failover never writes `model_ref` (runtime test and real-adapter matrix). Children use `subagentModel`, else the parent's pin, never the model that answered (M21 killed; child trace now passes `VerifyStep`).
- Candidates: filtering, order, dedup, tool calling, per-model margin and output reservation are pure and tested (M11–M14 killed). The health filter is advisory (M06 killed).
- Failover: availability → next candidate; capacity → strictly larger context (M07 killed); everything else stops. Capacity does not mark the model unhealthy (M04 killed).
- Retry-After: the adapter sleeps through at most 5 s and otherwise returns at once (M15 killed by `TestRetryAfterBeyondCapReturnsImmediately`). The registry stores the delay (A2).
- Timeout vs cancellation: only the run context means cancelled (M01, M23 killed). An adapter `cancelled` while the run context is alive is availability. `TimeoutError` has no `Unwrap`, which makes M28 an equivalent mutant.
- Adapter retries vs runtime failover: retries happen inside the adapter (≤2, availability only). Runtime failover happens once per class result. The cost is A6.
- Effort: override > default; `ClampEffort` behaves as designed (M19, M27 killed).
- Replay (I7) and I14: every logged decision recomputes, and every persisted step passes the strengthened `VerifyStep` (A1).

Mutation summary: 30 mutants. 26 were killed at the end. 2 are equivalent (M26, M28). M10 needed a compile-clean variant and was then killed. The remaining two survivors before the fix were the A1/A2 mutants, now killed.

## 8. Node baseline comparison (`shell tool streams stdout before process completion`)

- Node files unchanged between baseline and HEAD: `git diff --stat 16a3998 09d83f8 -- src tests package.json package-lock.json bin` is empty.
- Isolated baseline: `git worktree add --detach /tmp/lcx-m23-baseline 16a3998`, same Node v24.20.0, same host.

| Run | `16a3998` | `09d83f8` |
|---|---|---|
| `node --test --test-name-pattern='shell tool streams stdout…' tests/tools.test.js` ×30 | 25 pass / **5 fail** | 23 pass / **7 fail** |
| `npm test` ×3 | 2 green, 1 with this single failure | 2 green, 1 with this single failure |
| `npm test` final, audited tree | — | 211/211 pass |

- Mechanism: a failing run ends at about 77 ms, at the 70 ms assertion; a passing run takes about 185 ms in total. Spawning `sh -c node -e console.log` on this host takes p50 53 ms, p90 66 ms and max 111 ms to first stdout; 4 of 40 samples exceeded 70 ms.
- Classification: **genuinely unstable test** (timing budget close to Node child start-up), present on the baseline. Not M2.3-induced; 5/30 vs 7/30 is not a meaningful difference.
- No correction was made. Legacy Node behaviour is out of scope, and the Node loop is removed in M5.1. The smallest fix, if wanted, is to wait for the first stdout chunk with a deadline instead of a fixed 70 ms sleep. That would be a separate test-only change.

## 12. Desktop M2.4 compatibility contract

This audit confirms the contract in §10 of the implementation report, with these precisions:

1. `runtime.Options{Workspace, ProviderFactory}`. Desktop sets no factory.
2. `Supervisor.Start(ctx, id, AgentOptions{ModelRef, Effort, Input, …})` (JSON `modelRef`, `effort`). Send `ModelRef` only when the user changed it (F3); an empty value continues on the pin.
3. `SessionInfo.ModelRef` (JSON `modelRef`, omitted when empty) is the pin. `Provider`/`Model` are the provider id and upstream id of the last Start.
4. Rejected-Start sentinels:
   - `ErrUnknownModel` (text "model is not in the provider catalog");
   - `ErrModelWithoutToolCalling`;
   - `ErrInvalidEffort` — **not in the handoff's sentinel list; Desktop should add it**;
   - `openai.ErrNoEndpoint`;
   - a key-variable error naming the variable.
5. Terminal kinds:
   - `failed`: `provider:auth`, `provider:bad_request`, `provider:capacity`, `window_overflow`, `config`;
   - `interrupted`: `cancelled`, `provider:availability`, `max_steps`.
6. `Engine.Health()` does **not** expose model health (A3). Desktop must not expect it.
