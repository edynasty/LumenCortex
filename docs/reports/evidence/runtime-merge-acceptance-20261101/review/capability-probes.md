## U2 baseline (requested)

**Before this branch, no agent run could start a language server.**
- In `cog/r1a`, `runtime/agent.go:238-243` passed an LSP manager to the toolset only when a host-started server was already `Running`. `main` (`3e1c3cc`) has the same code at `agent.go:203-208`.
- `toolset.registerLSPTools` ran only when that manager was non-nil.
- `lsp.Manager.Start` was reached only through `Engine.LSPStart`. That is the host API used by Desktop's `StartLSP` (`LumenCortex-Desktop/app.go:413`) from the LSP settings panel.
- That host path has no trust check either. So a user who starts a TypeScript server by hand in an untrusted repository would also load its `tsserver.js`; that part is pre-existing and needs a user action.

**The new authority is the agent-reachable start.**
- At `15f9039`, `lsp_*` is offered whenever `Manager.Available()` holds: the command is on PATH and a matching file exists.
- The first model call starts the server, with no host action. This applies to read-only runs and untrusted workspaces; I traced the explore children in code but did not probe them.

**ADR-0013 does not cover language servers.**
- ADR-0013 gates project instructions, skills and project MCP servers. Its invariant is "No MCP process named by an untrusted workspace's `mcp.json` is started."
- It never mentions LSP: `grep -ciE 'lsp|language server'` returns 0 at both `15f9039` and `main`.
- The LSP config is global-only (`config/merge.go:105-113`), so a repository cannot choose the command. But the probe shows the built-in TypeScript server runs repository-chosen code: `typescript-language-server` prefers `node_modules/typescript/lib/tsserver.js` from the workspace over its bundled copy.

**Not probed:** rust-analyzer's `cargo check` running `build.rs`. `rust-analyzer` on this machine is a rustup proxy without the component ("Unknown binary 'rust-analyzer'"). That part stays [INFERENCE].

## Commit attribution

- `internal/mcp/session.go` and `internal/mcp/httpclient.go` do not exist in `cog/r1a` (`git cat-file -e` fails), so U4–U7 and U10 come from this patch.
- `reviewer.md` exists unchanged in `cog/r1a`; commit 468ff83 (the git-tool removal) is what made it wrong.
- Overwriting `mcp.json` with `write_file` is allowed by the T0-S1 guard on `main`, by design ("its other files, such as mcp.json and skills/, are project configuration", `toolset/path.go:25-27`). What makes it exploitable in U3 is new: a cached catalog that ignores `env`, and the on-demand start. In `cog/r1a`, `AgentTools` listed only running servers (`registry.go:383-403`).

VERDICT: REVISE

U1, U2 and U3 are confirmed P1s: each widens what a run can do. U1 lets a wake-up drop the host's tool filters. U2 lets a read-only run in an untrusted workspace execute repository code. U3 lets a workspace-policy run inject the environment of a process that a later read-only run starts without any host action. U4–U7 and RT-capability-1 are confirmed P2s; U8 and U9 are P3, and U10 is a partly confirmed P3.
