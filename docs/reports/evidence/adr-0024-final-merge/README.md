## Canonical OPEN P2 ledger

- **EDITING-PRE-01 / PRE-01 — existing-file truncate followed by write failure.** Original R3 record: [implementation report, R3 ledger](../../adr-0024-context-space-implementation-2026-11-18.md), workspace `TODO.md:31`, and workspace evidence `bench/evidence/adr-0024-r3-review-20261119/logs/r201-macos.log:164–173`. The recorded 8 MiB image probe `TestZZR3ENOSPC` destroys the 14,000-byte original (0 bytes remain) on main, a8b4786 and 2ba79ae. Existing-file `writeCAS` at original main `engine.go:681–729` truncates before writing; final `publish_file.go:116–230` `writeInPlace` still truncates at 156 and writes at 185. Both mechanisms trace to `e5777459f0e32d3070635836f7eebdac33f082dd`. Candidate's `TestR7InPlaceRLimitFaults` covers real zero-byte and partial write failure via EFBIG, not a fresh ENOSPC run. Existing risk not worsened in the compared path; partial state and dirty receipt improve detection, not recovery. Acceptance requires recoverable snapshots/version control including untracked data, monitored disk/quota headroom, and stop/re-read/restore on error. Closure requires original bytes preserved or recoverable, independently verified on real ENOSPC.
- **EDITING-PRE-02 / PRE-02 — destructive recovery race, with surviving forward-write/delete compare-to-mutate races.** Original R3 record: same ledger and workspace `TODO.md:32`, raw log `:63–70`. `TestZZR3RollbackRestoreVsForeign` appends externally to A after publication, forces a conflict on B, and observes rollback overwrite A with its old bytes on main, a8b4786 and 2ba79ae. Main `engine.go:731–774` `rollback`/`writeRestore`; unconditional recovery and forward truncate/write are already in `e5777459f0e32d3070635836f7eebdac33f082dd`. R5 worsened the rollback window; R6 did not remove it; R7 `dcc0589c2b89921506053713e03b6ae218f6ed5e` removed automatic compensation, ending that specific failure mechanism. The candidate still has compare-to-write/truncate (`publish_file.go:116–230`) and check-to-unlink (`deleteCAS`, `:376–438`) windows. The archived [differential probe](../adr-0024-r7r2-final/logs/11-pre02-baselines.txt) shows an append after truncate can be overwritten by the intended bytes, even with `published_verified`; mixed bytes can instead report dirty. No evidence candidate worsens these surviving windows. Risk acceptance requires exclusive/cooperative workspace writers, recoverability, and no blind replay; readback cannot report a write already overwritten. Keep OPEN P2 until independent remediation of the surviving race.
