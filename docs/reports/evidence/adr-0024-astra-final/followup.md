## Additional validation findings

The frozen read-only finding record is not rewritten. Two follow-ups were confirmed during wider verification of the first Astra code commit:

- **ASTRA-05 (P3, CONFIRMED, inherited from Sol).** Under the more permissive *zero-component* wildcard interpretation, `…/common/f.kt` can refer to the omitted root path `common/f.kt` as well as `zzzz…/common/f.kt`. This is distinct from literal `…`: the two ordinary nonempty interpretations are already unique in this case. The original archived checker actually recorded `ambStrict=1` on J3 but labeled the case `ok`. The output above the warning count is not a certificate. The candidate must also reject a leading directory wildcard when removing it exactly names a different attempted path, including in the positive-budget tail ladder. This is independent of path execution or aliasing.
- **ASTRA-PERF-01 (P3, CONFIRMED, intermediate Astra code only).** Commit `b1b459ac1e64400913a98f78427f0e7da974d166` can skip arbitrarily many rows whose compact JSON cannot fit. The existing per-row longest-common-suffix scan then becomes quadratic for one large same-basename group. Two `-benchtime=1x` trials at 64/256/1,024 actual failed rows ahead of `good.kt` measured about 6/52/662 ms per render. The correction computes the maximum common suffix of a full path from its adjacent neighbors in reverse-lexicographic order, once per large group, without changing file priority or the selected spelling. Small groups retain the cheap bounded scan. This is a scoped fix for that pairwise scan, not a proof that all path processing is linear.
