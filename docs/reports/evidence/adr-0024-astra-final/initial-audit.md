There is no random input-order labelling effect: label construction depends on owners, sorted neighbours and maxima, not insertion order. The stable within-rank prefix is intentionally order dependent. Keeping complete `(receipt,result)` pairs and permuting the same 40 files gave 3, 3, 3, 3, 2 and 3 rows (original, reverse, rotate, by-shape, seed 7, seed 31). Directory *order/depth in a path* and *input row order* are different problems. Per-path identity must already resolve over the whole batch: lengthening one label cannot make another file's previously ambiguous label unique. A global assignment or new shared dictionary is unnecessary.
