## State path rule

1. `Options.RepoDir`, when set (tests/self-checks); bound and checked like any other.
2. External directory, when it holds `lumencortex.db`.
3. `<workspace>/.lumencortex`, when it holds `lumencortex.db` and the external one does not (**legacy**, opened in place).
4. Otherwise the external directory, created `0700`.

External directory: `$XDG_STATE_HOME/lumencortex/workspaces/<name>-<hash16>` when `XDG_STATE_HOME` is absolute,
else `~/.local/state/lumencortex/workspaces/<name>-<hash16>`. `<hash16>` = first 16 hex of SHA-256 of the canonical
path; `<name>` = sanitized final component (≤ 40 chars). Canonical path = absolute, symlinks resolved, every component
spelled as the file system stores it (folds case and NFC/NFD). Project configuration (`mcp.json`, skills, `cognition.json`)
is read from `<workspace>/.lumencortex/` in both modes.

## Binding and legacy

- `metadata.workspace_binding` = `{canonicalPath, createdAt, coreVersion}`; no new migration.
- Mismatch or unreadable row → `ErrStateBindingMismatch`, row not rewritten, no replacement database.
- Missing binding: database that was at schema < 6 when opened is adopted; ≥ 6 is refused. **Today's maximum schema is 5**,
  so the "≥ 6 refused" branch is exercised by unit test (`TestMissingBindingByCreationSchema`) only; it becomes live when T1-S1's `0006` merges.
- First binding is written and read back under `bind.lock`, so concurrent first opens agree.
- Legacy database that Git tracks → `ErrRepositoryCarriedState`; a failing Git probe inside a repository also refuses; nothing is created.
- External state present beside a legacy database → external wins; `StateInfo().LegacyResidue` names the untouched legacy directory.
- No legacy database was migrated, moved or deleted (O-2 not granted; T0-S2 scope).

## Performance and compatibility

- Every `Open` takes `bind.lock` and, for a legacy/`RepoDir` database inside a Git repository, runs one `git ls-files`.
  Not measured.
- Each guarded file-tool call walks the protected state (≤ 4096 entries, else the call is refused) and `os.Stat`s each entry.
  Not benchmarked.
- Tests that open an Engine must set `XDG_STATE_HOME` (the `runtime` and `cmd/lcx-go` test mains do; `provider/anthropic` sets it per test).
- Windows: the code builds and vets; no Windows test was executed.

## Known security boundary

- **No OS-level isolation.** `shell` runs as the same user and can read or overwrite the database; `full` policy can bypass the guard.
- Not guarded: `search_text`, `find_files`, `git_status`, `git_diff`, the `lsp_*` tools (including `lsp_rename`, which writes files through the language server) and `read_skill`.
- `apply_patch` delete re-validates, then calls `os.Remove`; a swap of a parent directory in that window is not closed.
- Identity is compared against the files that exist when the call runs; a state file created later is covered by the name rule only.
- Legacy mode: untracked legacy databases that arrived by copy or archive are adopted when they carry no binding (schema < 6).

## Unresolved

1. Moving or renaming a workspace creates a new state; no re-bind command exists (T0-S2 / owner decision).
2. A crash after the schema-6 migration and before the binding write leaves a database that is then refused; recovery is manual. Becomes reachable only with `0006`.
3. Desktop still computes its own `repoDir`; thin adapter is a later task. Desktop passing `RepoDir` would be bound but not "the" external state.
4. SQLite-initialization fault injection is covered indirectly (unwritable root, cancelled context, unreadable binding row), not by a dedicated failing-driver test.
5. `StateInfo` field names and JSON shape are new public Core surface; confirm before Desktop uses them.
