### 2.1 Admission write-transaction count

The production store carries no counter. `internal/session/txcount_test.go` opens a second pool on the store's database file through a test-only driver (`sqlite3_txcount`, `ConnectHook` registering SQLite commit and rollback hooks; the hook fires once per committed write transaction). Result, all from `-race` runs:

| Operation | Write transactions |
|---|---|
| `AdmitRequest` (main) | 1 |
| `AdmitRequest` on a fenced session (the refusal is recorded) | 1 |
| `AdmitRequest` refused before any write (malformed digest) | 0 |
| `AdmitRequest` (`auto_effort`) | 1 |
| `AppendAnswered` | 1 |
| `SettleRequest` | 1 |
| Control: two separate session creates | 2 (proves the counter counts) |
| Capacity retry + failover + answer = 3 attempts | 3 admission + 3 settlement, 3 envelopes |

`TestEachStoreWriteIsExactlyOneTransaction`, `TestEveryAttemptTakesOneAdmissionTransaction`. At the agent level `TestEveryAttemptHasItsOwnEnvelope` asserts provider attempts = `AdmitRequest` calls = envelopes (3 = 3 = 3 for capacity retry plus failover; the capacity retry and the failover are separate attempts in that test, each counted). Together: each real provider attempt takes exactly one admission write transaction. A transaction counter over a full real Engine run is OPEN (the Engine's `Store` is opened inside `migrate.Open` and cannot be given a counting pool without a production hook).

## 6. OPEN items and limits

- Transaction counter over a complete real-Engine run (see 2.1).
- A request whose window holds no transcript row (`FirstSeq < 0`) is not sent: the run ends `failed/storage` (`request has no transcript window`) because such a request cannot be described by an envelope. No production session reaches this (the goal row always exists).
- The crash hooks stay in `runtime/agent.go` as nil-checked variables; they are test seams, not configuration.
- `realmodel` build tag compiled, not run.
- Merge into `cog/r1a` and G1 are outside this slice.
