## 2. Decisions

| # | Decision | Reason |
|---|---|---|
| D1 | Two fence reads. `sessionFence` (unchanged) is the **source** read: any fence on a session means nothing new may cite it, and a downgrade is refused. `consumerFence` is the **admission** read for the session's own work (`AdmitRequest`, `AppendAnswered`, `SettleRequest`, `AdmitExecution`, `commitFenced`, `SessionFenced`): it refuses while a fence on the session is not yet projected. | A reached reader must be able to continue with the revoked content withheld (§5 step 3) while staying withdrawn as a source. Same cost: one indexed read. |
| D2 | Projection state is one tombstone key, `projected: <epoch>`, set on the session's fence rows by `AcknowledgeProjection` in one write transaction that re-reads the newest epoch. No table, column or migration. | 0006's `source_fences` stays frozen. A revocation committed between the read and the acknowledgement makes the acknowledgement fail (`ErrFenced`); the next Start reads it. |
| D3 | Only a fence written by a revocation's walk on a **reached** session (`tombstone.revocation` names another session) can be projected (`reachedFence`). The revoked source itself, or a fence written by anything else, keeps the session refused (`IsolatedRevoked`). | The source's whole content is withdrawn; a hand-written or future fence kind must not be lifted by this path. |
| D4 | A thread is isolated (Start refused with `ErrFenced`, nothing written) when: the session itself is revoked; a fenced session started it (`fenced_parent`); its model output count differs from answered requests or a session-citing edge is lineage-incomplete (`incomplete_lineage`); an edge citing a fenced source names no transcript row or is not a `message` edge (`unmapped_source`); more than `MaxProjectionEdges = 1024` tainted edges (`bound`); or a main request **answered** with `fence_epoch` below the source's first fence carried the row in `[first_seq, last_seq]` (`exposed`). | Those are the cases where withholding rows cannot remove the content: a stored answer (and everything after it) may restate it. Laundering through answers, notes, Task State or user-visible model text is caught by the exposure rule, because each needs an answered request whose window held the row. |
| D5 | Withheld rows stay in the window with the same role, tool call id and order; only their content becomes `window.WithheldContent`. Task results of a revoked child are withheld in every delivery of that child. | Tool-call pairing and turn structure stay valid for every adapter; no tool is replayed and no turn is rewritten. |
| D6 | Projection runs in `Engine.Start` under the run lock, after Reconcile and **before** the Auto judge and BeginRun (`runtime/projection.go`, `runtime/agent.go`). The withheld seqs travel as `agent.Options.Withheld` into `run.load`. | Nothing is admitted for a Start before its projection is decided, so an isolated Start writes no envelope (not even a failed one) and changes no session fact. |
| D7 | Empty echo / provider incompatibility: a projected run is a new run, so it starts a new turn with no echo in memory (`internal/agent/send.go` turn rule, unchanged). An isolated thread is not rewritten: the user continues in a new session (clean task). | Plan §T3-S2 goal; no adapter-specific rewrite path exists or is added. |
| D8 | An `unknown` request (sent, no stored answer) does not isolate: nothing derived from it is in the transcript. It remains in the T3-S1 exposure report. | The provider may hold it; that is external exposure, reported, not projected. |

Write-transaction content: `AcknowledgeProjection` is one indexed read and one indexed update. `Projection` is a
read transaction: ≤1025 indexed edge rows, one indexed lookup per tainted edge and per withheld row. No git, file,
network or lock wait inside either.

## 7. OPEN items and known limits

- **OPEN (O-6):** real provider calls with a projected history are not run; only the deterministic adapter
  structure checks above.
- **Known limit:** a source session that has no answered main request (only a goal or user rows) is cited with an
  incomplete lineage, so its reader is isolated rather than projected (conservative, D4).
- **Known limit:** an isolated thread has no in-place recovery; the user continues in a new session. No UI is part of
  this slice.
- **Carried from T3-S1 (T3-S3 lane):** a parent whose pending `OriginTaskResult` delivery cites a revoked child that the
  walk did not reach; host read exits (`RecentMessages`, `MessagePage`, …) are T3-S3.
- **Cost:** per Start of a fenced session, one read transaction as in §3; per Start of an unfenced session, one
  indexed fence read. Not benchmarked.
