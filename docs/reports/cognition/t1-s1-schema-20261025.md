## 4. Store contract (`internal/session`)

| Method | Semantics |
|---|---|
| `AdmitRequest(ctx, RequestAdmission) (RequestEnvelope, error)` | Validates, writes `admitted`. Fenced session → `failed` envelope (reason `fenced`) + `ErrFenced`. Duplicate id → `ErrExists`. |
| `AppendAnswered(ctx, sessionID, requestID, protocol.Message) (int64, error)` | Transcript row and `admitted→answered` in one transaction; owner checked. Fence after admission → no message, envelope `unknown` (`fenced_before_answer`), `ErrFenced`. |
| `SettleRequest(ctx, requestID, Settlement) error` | `admitted→failed|unknown`, or `→answered` for a non-main purpose with a bounded decision. Refuses to settle a `main` request as answered. |
| `AdmitExecution(ctx, ExecutionAdmission) error` | Writes the `admitted` execution row; fenced session → `ErrFenced`, nothing written. |
| `CommitToolResult(ctx, ToolCommit) (seq, taskStateVersion int64, err error)` | Tool row, Task State, execution `admitted→completed|failed|outcome_unknown`, derived edges: one transaction. Fenced session or edge source → nothing stored, execution settled lineage 0, `ErrFenced`. |
| `Request`, `Execution` | Reads. |
| `Reconcile(ctx, sessionID) (int, error)` | Signature unchanged; see §6. |
| `SourceScopeRef(kind, ref) string`, `sessionFence(...)` | Fence key builder; fence read used inside every admission/commit transaction. |

Errors: `ErrFenced`, `ErrInvalidTransition`, `ErrRequestNotFound`, `ErrExecutionNotFound`, `ErrExists`, `ErrInvalid`.

Transaction form (`Store.writeTx`): one `s.db.Conn(ctx)`, `BEGIN IMMEDIATE`, callback receives only that
connection, `COMMIT` that is not cancelled with the caller's context (a context that dies between the last
statement and commit does not leave an open write transaction), rollback on any error. No Store method or
`s.db.*` is called inside a callback; no git, file, network or model work is inside one.

## 5. State machines

Request: `admitted→answered|failed|unknown`; `answered|failed|unknown` terminal; `prepared` exists only in memory.
Execution: `admitted→completed|failed|outcome_unknown`, all terminal. Every other pair, including self-pairs and
anything leaving a terminal state, returns `ErrInvalidTransition`. Each transition is a conditional
`UPDATE … WHERE state = 'admitted'` whose affected-row count must be 1, so two racing callers settle a request once.
`TestRequestStateMachineEveryPair` and `TestExecutionMachineEveryPairAndLineageRules` enumerate all pairs
against the real database.

## 6. Reconcile

Added `reconcileProvenance` to the existing `Reconcile` transaction (no new recovery engine): the session's
`admitted` request envelopes become `unknown` (`restart_without_answer`); its `admitted` executions become
`outcome_unknown` with `lineage_complete = 0`. Only `admitted` rows are selected, so a second call changes no
row (including `updated_at`), and completed/failed/answered rows are untouched. Nothing is executed or
resent. A missing session still fails and writes nothing. `TestReconcileSettlesProvenanceIdempotently` checks
a full-table dump before/after the second call. `TestPrepareRunDrawsAFreshRunIDAfterReconcile` shows
`prepareRun` itself settling a left-over request.

## 7. Run id

`newRunID` (128-bit `crypto/rand`, 32 lower-case hex) is called in `prepareRun` right after `Reconcile` and
before the Auto-effort judge, assigned to `loopOpts.RunID`. It is not a session column
(`sessions` has no run-related column: asserted through `pragma_table_info`), `BeginRun` is untouched, and
two Starts of one session get different ids.

## 10. Points for the Opus gate

1. `writeTx` commit semantics (uncancelled `COMMIT`, `commitThen` error carrying a committed-but-failing result).
2. Fenced-after-admission branches: they commit a state change and return an error; check callers can distinguish.
3. `derived_origins.kind` vocabulary is DDL-checked (`message|file|child_session|artifact|execution`) while
   `source_kind`/`origin_class` are validated in Go.
4. `support_status` defaults to `unverified` and the Store never sets another value: promotion is T2/T3 scope.
5. The mid-migration failure test builds a broken set by appending a failing statement to the embedded `0006`; it
   proves rollback of the ALTERs and indexes, not of a crash between `COMMIT` and the `user_version` write (SQLite
   sets it inside the same transaction).
6. Race: the one-off self-lock test failure noted in §8.
