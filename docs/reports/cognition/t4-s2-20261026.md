## 1. What changed

| Area | Change |
|---|---|
| `internal/session/evaluator.go` | `EvalRow` carries `EpisodeID/EpisodeStatus/PreFingerprint/PostFingerprint` (schema v6 columns, no new table or migration). `CloseEpisode` closes the `open` rows of one episode in one short `BEGIN IMMEDIATE` transaction; a row already closed is left as it is; an unknown status is `ErrEpisodeInvalid`. `DecidingEvalResult` returns only `closed` rows. |
| `internal/evaluator/evaluator.go` | `Satisfies(r, current, spec, inRun)`: approved digest+epoch, passed, current fingerprint, `closed` episode with pre = post = current; `human:<id>` counts on that alone, `runtime` only when `inRun`. `CheckVerdict` passes `inRun` through. | `internal/evaluator/run.go` | `Decide(ctx, specs, unit, unchanged)` is one episode: pre snapshot, fresh rows stored `open`, post snapshot and `unchanged` (configScope re-read) outside any transaction, then `CloseEpisode` as `closed`/`scope_changed`/`spec_unapproved`; cancellation closes stored rows `interrupted` (best effort, 5 s). Only a `closed` episode's verdicts pass. The `Evaluator` remembers the seqs it closed and the side-effect generation (`Mutated`); `Accept` writes a closed one-row episode. `Verdict.Episode` reports the episode status. |
| `runtime/checks.go` | `runChecks.Decide` passes the after-read of definitions+approval as `unchanged` (it used to flip verdicts after the fact); `Mutated` forwards; `SetApproved` = no approval ever, or the current set approved as it is. |
| `internal/agent` | `Checks` gains `Mutated()` and `SetApproved(ctx)`. The loop calls `Mutated` after every admitted execution or `MutatesWorkspace` result. `requiredChecks` fails a changed approved set as a whole (`(check set)` verdict). A non-interactive gate with any `spec_unapproved` verdict (unapproved check, definitions changed in the episode, changed set) ends `failed/spec_unapproved` (`KindSpecUnapproved`, `ErrChecksUnapproved`) without a correction. Unit results and corrections report a non-closed pass under the episode's status (`verdictStatus`). |
| ADR-0017 | Episode, predicate, set gate, exit and consequences sections; verification list. |

## 2. Decisions

| # | Decision | Reason |
|---|---|---|
| D1 | In-run registry is in memory on the run's `Evaluator`, not a column. | Plan §T4-S2 step 3 ("本 run 在内存中登记过"); a crash forgets it, which can only cause a rerun. |
| D2 | `Mutated` fires for every admitted execution (file, shell, MCP, `start_task`/`spawn_subagent`) and for a `MutatesWorkspace` result, whether or not the call succeeded. | A failed side-effect call may still have changed something; over-invalidating costs one rerun. Denied calls ran nothing and do not fire. |
| D3 | Host views (`SessionChecks`, `taskEvidence` after Apply) build an `Evaluator` with an empty registry: only a person's acceptance satisfies there. | DATA §3 cross-run default is a rerun; a host view is not the run that closed the episode. |
| D4 | Set-level gate only when the project ever had an approved set. | Gating a project that never approved anything and requires nothing would block every run with no bypass to protect; a never-approved project with required checks is already gated per check. |
| D5 | A pass in a `scope_changed` episode is an ordinary failure with a correction; `spec_unapproved` ends the run. | The model can fix a check that edits the tree; only the user can approve a definition. |
| D6 | Post snapshot and config re-read run outside the close transaction; the transaction is `UPDATE`s only. | Plan stop condition "post snapshot 需要放进事务"; G-1 rule on git outside write transactions. |

## 3. Failure paths

| Path | Behaviour | Evidence |
|---|---|---|
| Cancel mid-episode | stored rows closed `interrupted`; interrupted check stores nothing | `TestEpisodeInterruptedOpenAndLegacyRows` |
| Crash mid-episode | rows stay `open`; never deciding, never shadow an older closed row | `TestEpisodeInterruptedOpenAndLegacyRows`, `TestUndecidingRowsDoNotShadowAClosedOne` |
| Close fails (store) | `ErrStore` -> run `failed/storage`; rows stay `open` | existing `TestCheckDecisionFailuresEndTheRun` mapping; [INFERENCE] for the close itself, no fault injection run |
| Close repeated | no change to a closed row | `TestUndecidingRowsDoNotShadowAClosedOne` |
| Pre-episode rows after upgrade | never satisfy; checks run once again | `TestSatisfies` "no episode", `TestEpisodeInterruptedOpenAndLegacyRows` |

## 7. OPEN items and known limits

- **Cost:** a runtime pass is no longer reused across runs; every non-interactive run with required checks
  runs them once at its gate. T4-S3's start-of-run revalidation cap (≤2, ≤15 s) is not part of this slice.
- **Host views changed:** `SessionChecks.Satisfied` and evidence after Apply count only a person's
  acceptance. Desktop shows a past run's pass as "newest", not "satisfied". [INFERENCE] no Desktop test was run.
- **Desktop copy:** `spec_unapproved` exit kind has no label yet (shown raw by `kindLabel`); T7-S1.
- **Close failure:** no SQLite fault-injection test for a failed `CloseEpisode`; the path maps to
  `failed/storage` by the existing error mapping (not exercised).
- **Interactive turns:** `spec_unapproved` keeps the thread open as an obligation; there is no dedicated
  prompt for the user beyond `lcx-go checks status`.
- **R0 boundary unchanged:** a same-UID full shell can still rewrite the state DB; episodes do not change that.
