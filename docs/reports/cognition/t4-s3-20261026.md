## 2. Decisions

| # | Decision | Reason |
|---|---|---|
| D1 | Decide at Start, after seeds and queued edits, before `BeginRun`; the decisions ride the Start's Task State write. | Plan step 3 "run 启动时"; no new write path; a rejected seed refuses the Start before any check runs. Checks run outside any SQLite write transaction (G-1). |
| D2 | Use the run's own `runChecks`/`Evaluator`. | One predicate and one episode path (ADR-0017); a constraint pass registers in-run, so the completion gate does not run the same check again in that run (`TestConstraintIsDecidedFreshByEveryStart`: one stored pass per run). |
| D3 | A reused verdict (a person's earlier acceptance) is `unknown` for a constraint. | Contract: a constraint is met by a check run in the reader's current scope, or by an explicit deviation; an old acceptance is a cached result. The user path is `deviation`. |
| D4 | The cap counts check executions, not constraints; `unbound` and deviation cost nothing; a check shared by constraints counts once. | DATA §3 cap is on revalidation work ("不扫描全部历史检查"); deciding a binding is a store read. |
| D5 | An unapproved bound check is left to the evaluator (`spec_unapproved`, nothing runs) rather than pre-filtered. | One authority for approval; a mutation that pre-filtered changed no observable result. Cost: it takes one of the two slots, but approval is set-level, so all bound checks are unapproved together. |
| D6 | The list is not rendered into model requests. | O-5 not approved; push belongs to T5a-S2 (same boundary as T2-S2). |
| D7 | `scope` is matched by equality with the binding's approved scope; the check runs in the session's execution scope. | `bindingDigest` already covers scope (T4-S1); no scope algebra introduced. |

## 3. Failure paths

| Path | Behaviour | Evidence |
|---|---|---|
| Budget runs out mid-check | the check is stopped (Decide's context), its constraint and every later one `unknown` ("ran out"); the run starts and completes | `TestConstraintRevalidationBudgetDegradesToUnknown` (500 ms budget, `sleep 5` check, run < 4 s, marker shows nothing completed) |
| Third executable constraint | not run, `unknown` ("at most 2") | `TestConstraintRevalidationIsCapped` |
| Start cancelled during a constraint check | the check's process is stopped through `Decide`'s context; `decideConstraints` returns `ctx.Err()`; nothing of the Start commits (no Task State version, no running session, no request); no pass stored; the next Start decides fresh | `TestCancelledStartDuringAConstraintCheckSavesNothing` (check's later write never lands; Start returns < 3 s) |
| Thread revoked during a constraint check | the check finishes, but the Start's projection finds the thread revoked (`IsolatedRevoked`) and refuses it with `ErrFenced`; nothing commits | `TestRevokedDuringAConstraintCheckTheStartIsRefused` |
| Thread revoked after projection, before the Start transaction | **was a race** (found 2026-10-26): `BeginRun` had no fence read, so the Start committed `running` and a Task State version with the decision after the revocation, and the run failed at its first admission. Now `BeginRun` reads the consumer fence inside its `BEGIN IMMEDIATE` (one indexed read) and refuses with `ErrFenced` | `TestRevocationBeforeTheStartTransactionRefusesTheStart` (hook `testHookBeforeBeginRun`); fails with the fence read removed |
| Crash during the checks | Start never committed; episode rows `open`/`interrupted`, never deciding (T4-S2); next Start decides again | T4-S2 episode tests; no new state |
| Edit removed the constraint before Start | `setConstraint` no-op; nothing decided | `TestConstraintEdits` |

## 7. OPEN items and known limits

- **No host UI or CLI entry:** constraints are selected through `Engine.EditTaskState`; Desktop copy is T7-S1.
- **Constraint identity:** `constraintRef/constraintDigest` are host-supplied strings; no registry checks that the
  ref names an existing note or decision (by design: no Registry). The binding is what authorises.
- **Cost:** every Start of a thread with constraints spends up to two check runs / 15 s before the run, and writes a
  Task State version.
- **Not proven here:** cognitive benefit; cross-process interleaving of an edit and a Start beyond the existing
  inbox semantics.
- **Equivalent mutations (Start tests, 2026-10-26):** a cancelled check decided `unknown` instead of returning the
  cancellation still commits nothing (the Start transaction runs on the cancelled context and fails); skipping the
  Start's projection is caught by the `BeginRun` fence read instead (the revoked thread is still refused).
- **R0 boundary unchanged.**
