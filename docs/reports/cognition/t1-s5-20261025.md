## 2. Behaviour

- **Edges.** A Task State tool call: every new or changed entry version ← the issuing request (`agent_generated`), and a child a task gained (`child_session`) ← the request. `spawn_subagent`: `child_session` ← request. `wait_subagent` / `list_subagents`: the tool row ← each reported child as of its newest seq. User rewrite / take-over: new version ← replaced version (`message`, `user_decision`). User-started proposal: `child_session` ← proposal entry. Delivered task result: `task_result:<id>@<seq>` ← child as of `<seq>`. A note the user writes from scratch and the brief have no edge; the final answer is the answered main row (`answered_seq`, T1-S2).
- **Lineage propagates forward in the store.** A `message` source is complete only if the session records at least one edge to that exact ref and all are complete (an entry from before provenance makes every later rewrite incomplete). A `session` source is complete only if that session's newest answered main request at or before the `derived_from` seq is complete.
- **No laundering.** The rewrite keeps the user's wording, not user authority: Task State block, recall weight and `needsReview` all present it as agent text to re-check; the agent's cites remain the freshness basis.
- **Atomicity.** Version and edges commit together or not at all; a fenced edge source or session refuses the whole version (`ErrFenced`); invalid edges are refused before `BEGIN`.
