## 3. What changed

### 3.1 `threadctx.Catalog` (pure)

Input per thread (`CatalogThread`): id, relation kind, resolution, its notes, the store's facts per note, and the
ids of configured checks it ran. Output per thread (`LocatorEntry`), only when something is left to locate:

| Field | Source | Guard |
|---|---|---|
| `ref` | session id | generated id |
| `kind` | relation kind | `thread` / `subagent` / `execution`, anything else `other` |
| `resolution` | Task State resolution | `open` / `done` / `dropped`, anything else omitted |
| `citedPaths[]` | `path`+`blob` of a note's **own** cites | the note has cites, none of its sources is withdrawn, and **every** cite's blob equals the reader's current blob; ≤4 per entry, deduplicated, newest note first; a path over 256 bytes, with a comma/newline/control char, or padded is left out; anything left out sets `truncated` |
| `checks[]` | configured check ids the thread ran | ≤4, deduplicated, no spaces/commas/controls; status always `unknown` (T4-S3 is where a check's status in the reader's scope can become known) |

Not read at all: goal, brief, final, note text, a user rewrite's review cites, references (and their notes), check
logs and artifacts, tool specs. The builder has no parameter through which they could arrive.

### 3.2 `threadctx.RenderCatalog`

A fixed header and one line per entry:

```
- ref=<id> kind=<enum>[ resolution=<enum>][ paths=<path>@<blob>,…][ checks=<id>:unknown,…][ truncated]
```

At most 2 048 bytes and `MaxCatalogEntries` (8) entries; once a line does not fit, it and the rest are counted as
`(+N more)`. No entries render as `""`.

### 3.3 `Engine.LocatorCatalog(ctx, query, exclude)`

Read-only. Ranks threads exactly as `recall` does — the shared `rankThreads` (extracted from `recall`, behaviour
unchanged): newest 500 plus older term matches, fenced sessions and `exclude`'s subtree never candidates. Then per
ranked thread: one `SourceStatus` per cited note, the newest 64 `eval_results` rows for check ids, intersected with
the checks the configuration defines **now**; one `git` process (`FileBlobs`) for every cited path of every thread.
Returns `{entries, text}`.

## 7. OPEN items and known limits

- **OPEN (O-5 / T5a-S2, T6):** no request carries the catalog. Wiring it into requests, its placement in the fixed
  layer, and how it is recorded in the request envelope belong to the push decision.
- **OPEN (T4-S3):** check entries stay `unknown`; fresh-at-use is where a check's status can become known.
- **Known limit:** a path's text is workspace content (a file name); it is carried because the design allows
  verified workspace-relative paths. A path with a comma, newline or control character, or over 256 bytes, is
  left out, so it cannot break the line format.
- **Known limit:** check ids come from the newest 64 `eval_results` rows of a thread; an older check run is not
  a locator.
- **Cost:** per catalog, one ranking (as `recall`), ≤8 × (notes with cites) `SourceStatus` walks, ≤8
  `eval_results` reads, one `git` process. Not benchmarked.
