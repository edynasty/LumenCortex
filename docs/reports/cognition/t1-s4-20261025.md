## 2. Behaviour

- **Tiers.** files: `write_file`, `replace_in_file`, `apply_patch` (target paths only); workspace: `shell` and `mcp__*` with effective permission `exec` (an MCP spec without a permission is `exec`); admission only: other `mcp__*`, `start_task`, `spawn_subagent`; none: everything else.
- **Order per admitted call.** pre-state (outside tx) → `AdmitExecution` (one tx) → tool → post-state (outside tx) → `CommitToolResult` (one tx: row, Task State, post record, edges). `ErrFenced` at admission: the tool does not run, the run ends `failed/fenced`; any other admission error: fail closed (`failed/storage`), nothing runs.
- **Outcome.** returned OK → `completed`; returned not OK → `failed`; tool error → `outcome_unknown`, except a file tool whose targets the post-state shows unchanged and whole (→ `failed`).
- **Lineage.** an edge is lineage-complete only if the issuing envelope is, the coverage is `complete` and the outcome is not unknown; the store lowers it further (pre unavailable, fence). An unavailable or timed-out pre-state still runs the tool and is recorded `pre_unavailable`.
- **Cancellation.** unchanged: the cancelled call gets no tool row; the execution stays `admitted` until Reconcile settles it `outcome_unknown` at the next Start/Open.

## 7. OPEN

- An `admitted` execution row has `lineage_complete = 1` when the pre-state was available (ADR-0018 S1 semantics). Readers (T1-S5, T5a) must require a terminal outcome, not lineage alone.
- A cancelled call's execution stays `admitted` (session `interrupted`) until the next Start/Open of that session.
- Shell/exec-MCP edges attribute every change in the work tree during the call, including another writer's; changes to ignored files, outside the work tree, or to a path that stays clean are not seen while coverage still reads `complete`. This is the frozen bounded-status design; revisit at T5a if attribution errors appear.
- `start_task` and `spawn_subagent` admission is proven by the tier table test, not by a real call (the admission-only tier is exercised for real by the read MCP tool). Their derived edges are T1-S5.
- Transaction counts are proven at the loop (`TestStoreWritesPerCall`) and by S1/S2's counting driver per Store method, not over a full real-Engine run (T1-S7).
- Owed by G1: a non-author replay of the crash matrix (plan §8).
