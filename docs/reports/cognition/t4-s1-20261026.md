## 2. Decisions

| # | Decision | Reason |
|---|---|---|
| D1 | Approval is host state in `check_approvals` (schema v6, frozen by T1-S1), keyed by `project_id` = canonical workspace (ADR-0016). Never read from the repository or an imported DB. | Plan stop condition; an approval must not travel with a clone. |
| D2 | `specDigest` = `sha256:` of canonical JSON (id, kind, command, schema, files, timeout ms, required, source); `checkSetDigest` over all definitions sorted by id; the empty set has its own digest. The 8-byte fingerprint hash is not reused. | Step 2. Required and source are in the digest so "make optional" and a trust change alter it. |
| D3 | "Approved" means exact: newest set approval active, same set digest, its definition rows equal to the current definitions. Otherwise every definition runs with `ApprovalEpoch = 0`. | Partial approval of a changed set would let a removed/relaxed check go unnoticed. |
| D4 | Epoch = 1 + max epoch the project ever had (revoked rows included), in the approving transaction. | "恢复旧 digest 不会让旧 epoch 复活". |
| D5 | Each stored result carries `spec_digest` + `approval_epoch`; `evaluator.Satisfies` and `Store.DecidingEvalResult` require both to match the spec now. Pre-approval rows (NULL) never count. | One predicate for gate, reuse, acceptance, SessionChecks and evidence. |
| D6 | configScope: definitions and approval are always read from the Engine workspace (`Engine.approvedChecks`), never a session worktree. `runChecks.Decide` re-reads before and after; a set/epoch change in between yields no pass. The frozen `plan.checks` only selects ids. | Step 3. |
| D7 | Revocation on write runs inside `Store.CommitToolResult`'s transaction when a derived file edge (T1-S4/S5) names `lumencortex.json` (case-insensitive, `path.Clean`). `LastDefinitionWrite` uses the same predicate. | Step 4; no crash window between the write record and the revocation. |
| D8 | Unapproved spec: not run (verdict `spec_unapproved`, nothing stored), `AcceptCheck` → `ErrSpecUnapproved`, never satisfied. | An unapproved definition is not evidence of anything. |
| D9 | ConstraintBinding approval is separate (`Engine.ApproveConstraintBinding`, approvers user/team-decision/experiment-freeze); set approval approvers user/trust-flow/experiment-freeze. No tool or agent path calls either. | Step 6; agents only propose. |
| D10 | CLI `lcx-go checks status|approve <set-digest>` prints/calls the Engine API; `approve` refuses a digest the configuration no longer has (`ErrApprovalStale`). | Step 5; one entry for every host. |

## 7. OPEN items and known limits

- **Default change (O-4):** with no approved set, required checks are `spec_unapproved`: a non-interactive run with
  required checks cannot complete until a user runs `lcx-go checks approve` (Desktop UI is T7-S1). Owner decides
  before `main`.
- **T4-S2:** set-level gate for an **emptied** set or a removed only-required check (S1 shows it unapproved in
  `CheckApprovalState`; [INFERENCE, not tested] a completion gate with no required ids left still completes),
  closed episode, dedicated exit status, interactive behaviour.
- **T4-S3:** using bindings at satisfaction time.
- **Write-detection limits** (ADR-0017 Consequences): change+revert inside one shell command; writes to the
  global config (outside the workspace); a crash between a tool's write and its commit. A changed definition still
  changes the digest; only an exact revert escapes revocation.
- **R0 boundary:** approval covers definitions, not the scripts/tests they run, and is no isolation from a same-UID
  full shell.
- **Cost:** per Decide, two effective-config reads + one indexed approval read; per tool commit, an in-memory path
  comparison over file edges (one UPDATE only on a hit).
