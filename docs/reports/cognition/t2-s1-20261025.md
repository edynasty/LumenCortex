## 3. What changed

### 3.1 Transcript readback (25 turns without a note)

`read_thread {"id", "transcript": true}` adds one page of the session's stored messages; `before: <seq>` reads
further back (and implies `transcript`). A page:

- is read from `session_messages` through the existing `Store.MessagesBefore` (no new query);
- holds **whole tool groups**: a group is a non-`tool` row plus the `tool` rows after it. Groups are taken newest
  first while the page stays within **40 messages and 32 KiB**; a leading group whose start is older than the rows
  read is never taken — it starts the next page;
- projects only the provider-visible fields of each row (role, content cut to 4 KiB, tool calls with arguments
  cut to 1 KiB, `toolCallId`, `origin`). Nothing else a row holds is decoded into the result; `cut` and
  `complete` say when something was shortened;
- returns `nextBefore` (the oldest seq on the page, `-1` when nothing is older) and `hasMore`;
- for a single group larger than a page, returns **oversize**: `groupFirst`/`groupLast` locate the whole group, the
  page holds its first ≤40 messages each cut to a share of 32 KiB, `complete: false`, and `nextBefore` continues
  before the group. If that group starts more than 40 rows back, up to 500 rows are scanned to find its start.

The bounds are mechanism bounds, not tuned values. The fixed context window is not enlarged (stop condition not
hit): readback is an explicit tool result, paid only when the agent asks for it.

### 3.2 Recall past the newest 500 sessions

`recall` still ranks the newest `MaxCandidates` (500) sessions. When there are 500, it adds up to 500 **older**
sessions whose goal, final, brief, resolution or notes contain one of the query's tokens
(`ContextRowsMatching`: one CTE builds the lowered text once per older session, `instr` per term, at most 16
terms). Containment is a superset of the token match recall scores by, so an older session it leaves out cannot
score on an ASCII term. `ContextRows` and the "older than the newest 500" sub-query share the order
`updated_at DESC, id DESC`, so tied sessions split the same way in both (tested with 30 ties).

A hit carries `parentId` and `kind`, so a child task found by recall leads to its parent; `read_thread` of the
parent lists its children (fenced children as `withdrawn` with no goal).

### 3.3 Applicability

Every note `recall` or `read_thread` returns carries `applicability`, `origin` and `lineageIncomplete`
(`threadctx.Apply`), in this precedence:

| Applicability | When | Agent sees | Host sees |
|---|---|---|---|
| `withdrawn` | the note's session, or any source on its lineage, is fenced | id, author only | id, author only |
| `source_missing` | a cited file is gone in the reader's workspace | id, author, cites (locators); **no text** | text, labelled |
| `unknown` | a cited file changed; or a user note with nothing to check | text, `stale` | text, `stale` |
| `source_checked` | every cited file has the recorded blob | text | text |
| `unverified` | agent text, or the user's rewrite of agent text, with no cited source | text | text |

A fenced session is not a recall candidate at all; `read_thread` of it returns only id, kind, parent, status and
`withdrawn: true`.

**Agent vs host.** `Engine.ReadThread`/`Engine.Recall` are host APIs (Desktop's notes panel calls
`ReadThread`, `internal/backend/taskstate.go:91`, documented "Stale notes are flagged, never hidden"). The plan's
filter applies to agent retrieval (`检索结果…过滤 withdrawn 和 missing`), and host read exits are T3-S3's lane. So a
gone source withholds the text only for the agent reader (`threadReader`); the host keeps the user's own text,
labelled `source_missing`. A fence withholds for both. This keeps Desktop's contract while the agent cannot reuse a
derivation whose source is gone (DATA §2).

### 3.4 `SourceStatus` (plan §3.5, for T7)

`Store.SourceStatus(ctx, sessionID, ref)` / `Engine.SourceStatus` — read-only. From a derived target (a Task
State entry ref, a file ref, a child-session ref) it follows the newest non-`execution` edge per hop to the root,
**each edge at most once** (a rewrite back to earlier text repeats a ref; the walk then takes that ref's next older
edge instead of cycling), at most `MaxLineageHops` = 64 hops (DATA §4). It returns `Recorded`, the target's
`Origin`, `RootKind`/`RootRef`, `Hops`, `LineageComplete` (false when unrecorded, a hop has no edge, an edge says
incomplete, or the bound is reached) and `Withdrawn` (the session or any source scope on the chain is fenced, one
query). It writes nothing.

## 9. OPEN items and known limits

- **OPEN (T3-S3):** `RecentMessages`, `MessagePage` and the other host read exits do not filter fenced content;
  this slice covers `read_thread`/`recall` and `Engine.ReadThread`/`Engine.Recall` only.
- **OPEN (T2-S2):** the locator catalog is the next slice; this one adds no catalog.
- **Known limit:** older-than-500 candidates are found by substring containment of ASCII-lowered text; a query
  whose only tokens are CJK bigrams still matches by `instr`, but case folding is ASCII only.
- **Known limit:** a transcript page cuts content to 4 KiB per message and arguments to 1 KiB; a reader that needs
  the whole body of one message has no tool for it in R1a.
- **Known limit:** an oversize group whose start is more than 500 rows back is located only within those 500 rows.
- The `read_thread` tool spec changed, so the `toolSpecsDigest` of requests built after this commit differs from
  before; that is the intended record of what the provider was sent.
