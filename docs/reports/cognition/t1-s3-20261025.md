### Outcome mapping (Auto judge)

| Judge outcome | Envelope | Effort used |
|---|---|---|
| reply parses to a level | `answered`, `decision_json = {"level":"<reply level>"}` | the reply level, then the host ceiling |
| reply unparsable | `unknown`, reason `unparsable` | `HeuristicEffort` |
| judge timeout (`effort.auto.timeoutSeconds`) | `unknown`, reason `timeout` | `HeuristicEffort` |
| provider error | `unknown`, reason = provider class (`auth`, `capacity`, `availability`, `bad_request`, …) | `HeuristicEffort` |
| run cancelled | `unknown`, reason `cancelled` | Start ends with `context.Canceled` |
| session fenced at admission | `failed`, reason `fenced` (written by the store) | Start ends with `ErrFenced`; judge not called |
| no judge model, or its client cannot be built | none | `HeuristicEffort`, fallback `no_model` |
| resumed turn reuses its decision | none | the persisted level |

The envelope records the level the *reply* was read as, before the ceiling narrows it; the decision log
still records the level the run uses. ADR-0018 names `decision_json` as the Auto judge's
`{"level": …}`, which is why the envelope keeps the reply.

## 5. Transaction discipline

- `AdmitRequest` is called with a fully built admission: the seqs come from `classifyTurn` (read before),
  the digest is `sha256` of the pending input (computed before), and the request id is 128 random bits
  (drawn before). The store's transaction only reads the fence and inserts the row (plan §3.1).
- Admission happens under the run lock, before `BeginRun`, so the lock order is “run lock, then
  transaction” (plan §3.1.3).
- One admission per judge call: the in-flight read shows exactly one new `admitted` row per call and no
  other open request (test 1). Settlement is a second, separate transaction and never retried.
- A settlement failure fails the Start (fail-closed); the still-admitted row is reconciled to `unknown`
  at the next Start. A cancellation is the Start's reported cause even if its settlement fails.

## 8. OPEN items and known limits

1. **OPEN — the stored-input case does not name its input row.** When the judge classifies a user row
   that is already in the transcript (the common fresh-session goal), the envelope records the context
   seqs but no seq for the input itself, and `pending_input_digest` is empty by definition. The frozen
   admission fields (`prev_user_seq`, `last_assistant_seq`, `pending_input_digest`) have no slot for
   “the stored input row”, and `first_seq`/`last_seq` are documented as a main request's window, so this
   slice does not overload them. `lineage_complete` is written as 1 because the request is described by
   the two context seqs plus either the digest or the turn's stored user row; if T1-S7/T3 exposure needs
   the exact row, that is a contract change request (new field or a documented use of `last_seq`).
2. **OPEN — `projection_version` and `refs` are empty** for `auto_effort`: the judge offers no tools and
   no Task State. `projection_version = 0` means “no projection”. A rubric version, if it is ever needed
   for exposure, is another contract addition.
3. **Known limit — a settlement failure after an answered judge fails the Start.** The judge level is
   lost and the envelope is reconciled to `unknown` at the next Start. Fail-closed was chosen over
   proceeding with a provenance gap; a retry of the Start re-runs the judge.
4. **Known limit — the CLI still builds the curator provider** before `GovernorPlan` refuses it. No
   request is made (asserted), but `--curator` keeps its configuration preconditions. Removing
   `governorCurator` entirely was out of scope (it is covered by `provider_test.go` as the D1 config
   path).
5. **Pre-existing, not introduced here:** `runtime/governor.go` and `runtime/governor_test.go` were
   already not `gofmt`-clean at `4c20959` (joint gate §7 P3). This slice kept their local style; every
   other touched file is clean. Reformatting them would have mixed a 200-line whitespace diff into the
   change.
6. Not run: `-race` across the whole repository (only the three packages the gate names were run with
   `-race`); real-model provider tests (`-tags realmodel` was vetted, not run — they need paid APIs).
