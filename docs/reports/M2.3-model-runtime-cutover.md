## 3. Phase 1 — F1 security correction

Problem: `provider/openai.New` fell back to `https://api.openai.com/v1` when neither `Endpoint` nor `BaseURL` was set, so a
provider configured with only an `apiKey` sent the key and the transcript to api.openai.com.

Change:
- `provider/openai/client.go`: `defaultBaseURL` deleted; `New` returns the new `openai.ErrNoEndpoint` when neither is set.
- `cmd/lcx-go/provider.go`: `newProvider` wraps the error with the model ref and provider id (never the key).
- `cmd/lcx-go/main.go`: the legacy cognition binding wraps the same error; it is removed in Phase 6.

Tests (all in the Phase 1 commit):
- `TestNewRequiresEndpointOrBaseURL` (adapter): empty/blank/trailing-slash-only URLs are refused; error does not contain the key; explicit baseURL and endpoint still construct.
- `TestProviderWithoutDestinationIsRefusedBeforeAnyRequest` (CLI, real entry point): `agent` and `resume` fail before any session is created; every proxy variable points at a recording server which sees zero requests; the key never appears in output; the goal text is not persisted.
- `TestCognitionBindingRefusesDefaultURLWhenRemovedBaseURLIsSet` extended: generic binding without baseURL is refused even without `LCX_BASE_URL`.
- Existing `TestCLIAgentAndResumeUseUnifiedConfig` and `TestProviderFromConfigBuildsTheConfiguredClient` still pass (explicit providers work).

Result: `go test -count=1 ./provider/... ./cmd/... ./runtime/... ./internal/...` all `ok`.
