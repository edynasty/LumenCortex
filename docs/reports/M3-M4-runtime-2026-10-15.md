## M3.1 decisions (implementation level, within the approved design)

- **Packages.** `internal/taskstate` holds the pure parts: the state document, work units and `Progress` (moved verbatim from `internal/cognition`, which keeps only the dormant Governor), references, resolution, inbox edits and the Task State block renderer. SQL lives in `internal/session` next to the transcript, so a Task State version commits in the same transaction as the row that caused it.
- **History.** One row per version; a write inserts `base+1` and the primary key turns a concurrent write into `ErrTaskStateConflict`. Versions older than 32 behind the newest are pruned in the same transaction (contract `PutTaskState`).
- **Inbox.** Host edits (`brief`, `reference`, `resolve`) are one `INSERT` into `task_state_inbox`, with no run lock. A run applies them at the next step boundary before building the request, in one transaction with the new version (reason `user`); Start applies them in its `BeginRun` transaction. Host reads return the newest version with pending edits applied in memory and their count, so an idle thread shows its edits without anyone taking the run lock.
- **References.** The agent writes them only through `reference_suggest`, which adds `suggested` entries. It never changes an entry the user set and never re-suggests an excluded target.
- **Resolution.** Manual changes go through the inbox (`ResolveThread`). Auto-done before M4.1 requires a host workflow that `CanFinish`, no open work unit, no pending application and no model cancellation since the last reopen; it never replaces a resolution the user set. A new obligation (unit created, successful mutating tool) reopens a `done`/`dropped` thread with `by: reopen`. "Ready for review" is derived on read and not stored.

- **Downgrade tests.** `TestDowngradeRoundTrip` and `TestDowngradeEveryBoundary` write sessions and Task State at the latest schema, step down through every migration boundary, check the restored metadata, and upgrade again. Mutation check (2026-10-17): removing the progress restore from `0003_task_state.down.sql` fails both.

## M3.2 decisions (implementation level, within the approved design)

- **Window builder.** `window.Build` (port of `verify/go/window`) constructs `System ++ [Task State block] ++ <contiguous suffix of whole groups>` under a token budget. Groups are atomic (user alone, or assistant + its tool results) and taken newest→oldest. `Entry.EchoTokens` counts run-memory echo while its row is in the current turn.
- **Pairing validation.** `window.Groups` enforces I2 and returns `ErrUnpaired` for orphan, duplicate or missing results; the loop ends such a run `failed/transcript_unpaired`.
- **Transcript source.** The loop reads the transcript from `windowStartSeq` once per run with the stored seqs (`Store.Transcript`), appends every row it writes, and drops from memory the leading groups no window of the run's largest model can include (their count stays in the dropped total).
- **Per candidate.** The window is built for each failover candidate with that candidate's budget: context, output reservation (`MaxTokens` or the model's output limit) and 5 % margin. `ErrOverflow` moves to a candidate with a larger context, else `failed/window_overflow`.
- **Capacity retry.** A capacity rejection is retried once on the same model with at most half the rejected request's transcript tokens (`window.CapacityRetry` / `RetryMargin`); that limit holds for the model until the run ends.
- **Decision log.** `window.dropped` (groups left out) and `window.capacity_retry` are logged decisions that `VerifyStep` replays (I7); each step record carries `window: {firstSeq, dropped, tokens}`.
- **Row-count option removed.** `AgentOptions.RecentMessages`, `agent.Options.RecentMessages` and `LCX_RECENT_MESSAGES` are gone (design §4.9).

## M3.2 §4.6 decisions (reasoning echo, resume and turn rows)

- **Opaque echo.** `protocol.Echo` (`protocol/echo.go`) holds a copy of the adapter's bytes, a kind and an adapter-reported token size. It refuses JSON and text marshalling (`ErrEchoNotSerializable`) and formats/logs as its size only. `ProviderRequest.Echo` (aligned with `Messages`) and `ProviderResponse.Echo` are `json:"-"`.
- **Adapter.** The OpenAI-compatible adapter reads `reasoning_content` (whole and streamed responses) into `ProviderResponse.Echo` under `reasoning.echo: reasoning_content` and sends `Echo[i]` back as `reasoning_content` on assistant messages only; `none` neither returns nor sends it. The mode comes from the resolved model (`config` default: `reasoning_content` for `reasoning.format: deepseek`, else `none`).
- **Run memory.** `run.turn` (`internal/agent/transcript.go`) maps the seqs of assistant rows this run produced in the current turn to their model and echo. A user row (input, `resume`, `turn`, `completion_blocked`) ends the turn, empties the map and zeroes those rows' `EchoTokens`; trimming leading groups drops their entries, so memory is bounded by the window. `requestEcho` aligns echo with the window from `Result.FirstSeq` and includes only the target model's entries.
- **Resume row is Start's.** `BeginRun` appends a `resume` user row in the Start transaction when there is no `Input` and the newest row is not a user row (§3.2, §4.6 rule 1). The loop never writes `resume`.
- **Turn row is the loop's.** Before each request (per candidate), `TurnBoundary` applies `NeedsTurnBoundary`; when due the loop commits a `turn` user row before the request and logs `turn.boundary` (kind `turn`), which `VerifyStep` replays (I7). The newest group's base estimate excludes echo (§3.3 step 4).
- **Removed.** The comment in `provider/openai/factory.go` reserving echo for M3.2.

## M4.1 decisions (implementation level, within the approved design)

- **Packages.** `internal/evaluator` holds specs (`Specs` from `config.Check`, with `Source`), the fingerprint, check execution, `Decide` (CheckVerdict), `SatisfiedAll` (Satisfies) and `Accept`. SQL for `eval_results` and `artifacts` lives in `internal/session/evaluator.go`; migration 0004 and its down file add both tables. `AppendEvalResult` takes `BEGIN IMMEDIATE` before reading `MAX(seq)`, so two processes cannot write the same seq.
- **Execution.** Test and build checks run through `shell.Runner` in the session's workspace (its worktree when bound), with the process group killed on timeout or cancellation (`1b29bb9`). Schema checks run in process. A fresh result stores a `log` artifact; a non-passing result also stores the `diff` its fingerprint covers. Artifacts are capped at 1 MiB, head and tail kept.
- **Work units.** Units list configured check ids in `checks`. `work_unit_update` takes only `id`, `status`, `summary` and `evidence`, and refuses any other key, so the model cannot write a result. Setting `completed` decides the unit's checks through the evaluator. The verdicts (`UnitCheck{check, status, provenance, seq}`) are recorded on the unit either way, and the unit completes only if all pass. `work_unit_create` refuses unconfigured check ids. Task State versions written before M4.1 still decode; their model-written `verification` fields are dropped and count for nothing (`TestPreEvaluatorVersionDecodesWithoutModelVerdicts`).
- **Completion gate.** The gate's order is workflow → open units → required checks. Failing required checks append one `completion_blocked` row naming each check with its status, artifact hashes and the last 2 KiB of output; the run continues. A failure to decide checks ends the run: cancellation is `interrupted/cancelled`, a store failure is `failed/storage` (`evaluator.ErrStore`), and an uninspectable workspace is `failed/config`.
- **Evidence rule.** `taskstate.Evidence.Checks` carries each required check's satisfaction at the current fingerprint. An unsatisfied one is the `checks` obligation. Acceptance (ADR-0006 D2) is a workflow that `CanFinish`, all required checks satisfied, or every unit completed with passing verdicts. A unit completed without checks rests on the model's word and is not acceptance. The latch records `check:<id>@eval:<seq>` refs before the workspace refs.
- **Apply latch.** `ApplySessionWorktree` applies the evidence rule after a successful cherry-pick, under the run lock it already holds (reason `apply`). It applies queued inbox edits first, so a queued user resolution is never overridden. Applying discharges only pending application. A failure to latch is published as `task_state.evidence_unavailable` and does not fail the Apply.
- **Agent seam.** `agent.Loop.Workspace` is replaced by `Evidence` (workspace and check evidence; the loop adds the workflow's verdicts). `agent.Loop.Checks` (interface `agent.Checks`) is implemented by the runtime over the evaluator. The run's checks come from the same config load as its models (`modelPlan.checks`).
- **Host API** (`runtime/checks.go`): `SessionChecks` (configured checks, satisfaction and deciding result at the current fingerprint, the newest result, and warnings for dropped untrusted checks; read-only and lock-free), `CheckResults` (paged newest first; `-1` for the newest page, as for `MessagePage`), `CheckArtifact`, and `AcceptCheck` (a `human:<actor>` result; `ErrNoFingerprint` outside git, `ErrUnknownCheck` for unknown or untrusted checks). Acceptance is evidence, not a resolution: it is latched at the next run end or Apply.
- **Not added.** A host "run checks now" operation and a CLI acceptance command: neither is in the M4.1 row. Desktop M4.2 consumes the four calls above.
