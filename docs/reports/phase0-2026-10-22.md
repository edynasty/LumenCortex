Deviations from the plan, all recorded in the slice reports:

- The `anthropic-messages` format vocabulary is `{"", "adaptive"}`; `""` is the existing budget encoding.
  `none` is refused for that package. Validation runs on the merged catalog because a workspace entry
  inherits its package from the global file.
- An unimplemented format is a `bad_request` before any request is sent.
- The effective prompt reports purpose and authority as one `builtin` layer (that is how the run sends
  them) and Task State as a `task-state` layer (it travels as the first user message).
- `Engine.Skills(scope)` does not carry `blockedByTrust`; hosts combine `EffectivePrompt().trusted` with
  `Skill.Scope`.

## Limits and open risks

- The smoke used the local gateway, not the official Anthropic endpoint; signature-binding conclusions
  do not transfer (PROVIDER-002 stays P3).
- The owner's global config does not yet declare `reasoning.format: "adaptive"` for the Claude 5.x
  models; until it does (Desktop's model editor or a manual edit), those models still fail with the
  gateway's HTTP 400. The smoke set it only in the temporary copy.
- `internal/agent/auto.go` sends `temperature: 0` for the effort judge; an adaptive model drops it, a
  budget-format Claude model judged at level `none` would still send it.
- `xhigh` is not an LC effort level (PROVIDER-003).
- ADR-0014 needs owner acceptance before phase 1 implements it.
