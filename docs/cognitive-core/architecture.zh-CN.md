# Cognitive Core 总体架构

Cognitive Core 按七种职责组织。它们不是七个独立服务，也不是七个数据库，而是同一个 Go 认知系统中的不同工作。

## 七个认知领域

| 领域 | 负责什么 | 主要输入 | 产生什么 | 当前边界 |
|---|---|---|---|---|
| 记忆 Memory | 保存任务经历、事实、关系、证据和经验 | Session、工具结果、人工输入、检查结果 | 带来源和适用范围的记录 | Go main 有 Session、Notes 和知识存储；更完整的认知候选尚需单独合并 |
| 注意力 Attention | 从大量信息中挑出当前任务需要的内容 | 任务目标、当前状态、查询、知识关系 | 有优先级且数量受限的上下文 | Go 有词面/符号检索基础；Node 历史算法不能算 Go 能力 |
| 推理 Reasoning | 根据知识和证据提出解释、比较原因、决定下一步 | 上下文、证据、约束和未知项 | 假设、判断、问题或行动建议 | 模型负责推理，Go 提供约束；通用证据充分性判断尚未完整建立 |
| 学习 Learning | 从任务结果中提取可复用经验 | 任务经历、操作、结果和反例 | 带前提和限制的经验候选 | 候选实现有提取、验证、采纳和反馈；通用经验抽象与迁移仍不完整 |
| 信念修订 Belief Revision | 根据新证据修正、失效或保留旧判断 | 新证据、冲突、来源变化、时间 | 新版本、冲突或失效状态 | 已有部分来源、冲突和新鲜度机制；不等于通用逻辑推理 |
| 认知治理 Governance | 控制知识如何被采纳、修改、归档和删除 | 候选变更、证据、策略和资源限制 | 允许或拒绝的计划与状态变更 | Go main 的 Governor 主要支持只读分析、计划和验证；不宣称自动执行全部治理操作 |
| 验证 Verification | 检查一项判断是否有合适证据支持 | 判断、来源、范围、时间和实际检查结果 | 通过、失败或未知的验证记录 | 能验证实际执行的检查；检查通过不代表证明了检查范围以外的结论 |

## 七个领域如何配合？

一次任务的大致过程：

1. **记忆**提供以前发生过什么。
2. **注意力**挑出与当前任务有关的信息。
3. **推理**根据这些信息提出解释和下一步。
4. **验证**检查关键判断是否有真实依据。
5. **Agent**执行获准的操作。
6. **学习**记录操作和结果，提取可能有用的经验。
7. **信念修订和治理**处理新证据、错误经验、过期信息及权限。

新结果再进入记忆，供后续任务使用。

这是目标工作关系，不代表当前 main 已经打通全部环节。

## 所有领域必须共用的规则

### 范围

知识必须说明适用于哪个项目、环境、组件或任务。不能把一个项目里的结论直接套到另一个项目。

### 时间

区分信息何时产生、何时生效、何时失效。最近使用不等于正确，时间久也不等于过期。

### 来源

记录信息来自哪里、由谁产生、经过什么检查、从哪些信息推导而来。模型自己说“正确”不是证据。

### 适用条件和未知状态

记录经验的前提、不适用条件、冲突和未知项。无法确认适用时，不能当成当前有效知识。

### 状态变化

提出、验证、采纳、使用、反馈、修订、失效、归档和删除都必须有明确记录，能够追溯和恢复。

### 隐私和归属

区分原始来源、共享经验、每个使用者自己的采纳记录和反馈。删除一个使用者的数据，不应误删其他人的独立数据；原始来源被撤销时，依赖它的内容必须按规则失效。

## 目前还没有解决完整的问题

- 事实、假设、经验和决策是否共用一套完整状态模型。
- 证据不足时，如何决定继续查证、提问、暂缓还是停止。
- 如何从具体经历中提炼出能在不同任务使用的方法。
- 如何发现自己的知识缺口和推理假设有误。
- 如何在所有读取、回放和删除路径上保持一致的隐私规则。
- 如何压缩和保留长期记忆，同时不丢失关键来源和反例。

先检查现有七个领域能否解决这些问题，不要为了每个问题都新建一个服务。
