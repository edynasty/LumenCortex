# 记忆管理：短期、长期、压缩和保留

记忆管理不是把内容无限保存，也不是定期删除很久没访问的数据。系统需要保留原始经历，同时从中整理出以后真正有用的知识。

下面四种记忆是逻辑分类，不要求建立四个数据库。

## 四种记忆

| 类型 | 保存什么 | 主要用途 | 生命周期 |
|---|---|---|---|
| 工作记忆 | 当前目标、约束、证据、待解决问题 | 支持当前 Run 的理解和行动 | 当前任务窗口，需要时保存任务状态 |
| 情景记忆 | 某次任务发生了什么、执行了什么、结果如何 | 还原经历，作为经验来源 | 按隐私和保留规则保存 |
| 语义记忆 | 已整理的事实、概念、关系和适用条件 | 回答后续任务中的知识问题 | 长期保留，但证据变化时要修订 |
| 程序性记忆 | 在什么条件下，用什么方法解决什么问题 | 让 Agent 在后续任务中复用方法 | 前提仍成立且证据有效时保留 |

短期和长期主要是保留策略，不一定对应不同数据库。

- 短期内容通常是当前任务信息、近期经历或尚未验证的候选。
- 长期内容应有持续价值和可靠来源，不能仅因为保存时间长就当成正确。
- 形成摘要后仍应保留原始经历，不能让摘要取代原始证据。

## 从任务经历整理出长期经验

目标过程：

1. 保存任务经历和真实结果。
2. 区分实际观察与模型解释。
3. 提取可能重复出现的问题模式。
4. 写清适用前提、处理方法、预期结果和不适用情况。
5. 保留来源和证据。
6. 检查反例和适用范围。
7. 验证通过后，才允许在相应范围内复用。
8. 记录每个使用者自己的使用结果。
9. 根据反馈修订、缩小适用范围、失效或保留。

一次成功只能证明这一次成功，不能直接证明某种方法普遍有效。

## 三种不同的压缩

不要把以下操作混为一谈：

1. **上下文筛选**：为下一次模型请求挑选有限信息，不应改写长期记忆。
2. **经历摘要**：把一次任务整理成摘要，但保留原始经历和来源。
3. **知识整理**：从多次经历中归纳有条件的方法，保留反例和证据，验证后再扩大使用范围。

简单截断文字不是知识压缩。如果摘要无法追溯原始来源，就不能代替原始记录。

## 使用频率、最近使用和实际价值

这几个指标含义不同：

| 指标 | 表示什么 | 不能代表什么 |
|---|---|---|
| 最近使用 | 最近一次查看或使用时间 | 最近不等于正确 |
| 使用频率 | 有多少次独立任务使用过 | 重复读取不等于多次验证 |
| 实际价值 | 使用后是否改善结果或降低成本/风险 | 成功不一定由这条经验造成 |
| 证据强度 | 有什么来源支持它 | 模型自评置信度不是证据 |
| 适用条件 | 当前环境是否满足使用前提 | 文字相似不等于条件相同 |
| 稳定程度 | 事实是否容易变化 | 很久没用不等于失效 |
| 依赖关系 | 哪些知识或决策依赖它 | 删除一个使用者不应误删其他人的数据 |

重复尝试、重试和重复读取不能增加独立使用次数。频率统计必须按独立任务或经历去重。

当前 Go 的 Thread Recall 有最近使用时间加权，代码注释说明使用 30 天半权重。这只影响检索排序，不是自动过期规则，也不是所有记忆共用的衰减策略。

## 归档、失效和删除

不能只按 LRU 或 TTL 删除重要知识。

保留决策至少要考虑：

- 来源和证据是否还有效；
- 项目、环境和时间范围；
- 内容是否容易变化；
- 是否被不同任务独立使用；
- 使用后是否确实有帮助；
- 是否属于安全规则、罕见故障或重要反例；
- 是否还有其他知识依赖它；
- 隐私删除要求。

要区分五种操作：

- **降低优先级**：少显示一些，但不改变知识有效状态。
- **过期**：超过有效时间或前提已不成立。
- **撤销/失效**：来源、隐私或正确性发生问题，禁止继续使用。
- **归档**：从常用检索中移出，但按规则保留历史。
- **删除**：按隐私或保留政策清除内容，并处理依赖数据。

很少使用的安全规则仍可能非常重要；经常使用的错误经验也不能因为频率高而保留为正确知识。

## 容量管理

先限制每次使用多少信息，再管理长期存储：

- 限制当前任务上下文和 Token 数量；
- 限制每次检索的候选数量和图遍历范围；
- 限制每批整理的经历数量；
- 为历史、附件和摘要设置明确容量；
- 摘要必须能追溯来源；
- 容量不足时明确报告，不能静默丢弃证据。
