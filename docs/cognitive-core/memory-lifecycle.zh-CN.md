# 记忆生命周期：短期、长期、压缩与保留

**2026-11-13 未合并候选。**[English](memory-lifecycle.md) · [架构](architecture.zh-CN.md) · [实际验证](../reports/cognitive-core-final-completion-2026-11-13.md)。

## 四种职责，一个 Store

| 类型 | 权威数据 | 如何用于未来任务 |
|---|---|---|
| 工作记忆 | Task State、Notes/Notebook 和当前有界上下文 | 普通 Agent 使用目标、约束、未知项和已检查结果；压缩不会把隐藏推理写成长期记忆。 |
| 情景记忆 | Session/Run、已回答请求、执行 ID、终态和 `eval_results` | 提取引用真实经历与版本，不相信模型自称成功；失败和执行不完整分开记录。 |
| 语义记忆 | Maintenance 候选、原生 Graph 的 belief/entity/abstraction 等 | 精确断言通过宿主绑定检查取得证据；摘要保存 `Sources` 和固定版本的 `Dependencies`，文字仍是提案。 |
| 程序性记忆 | 原生 Graph 版本中的类型化 Experience | 当前条件、原操作轨迹和独立消费者明确应用，将旧经历接到新任务。 |

短期、长期是职责和保留策略，不是另建数据库。`MemoryClass()` 提供 Graph 逻辑分类，Task State 和 Session 保持原存储契约。

## 从经历到实际复用

1. `propose_experience` 为当前 Run 保存有限的结构化候选。模型不能自填权威来源、成功结果或证据等级。
2. 现有任务结束边界调用 `finalizeCognitiveRun`，根据真实来源提取、验证。原始任务/Run、工具参数摘要、执行 ID、文件版本和检查记录不可改写。
3. 轨迹截断或不完整、未获批准、条件失败、结果不受检查支持，都不能验证为成功程序。负向预期保持负向含义。
4. 召回只选择范围内的相关定位信息；采纳独立检查当前条件，先持久化单次采纳身份，再返回策略。
5. `apply_experience` 显式接收原工具/参数序列，重查定义/条件并提交准入。每个动作观察当前 Workflow，执行/Task State/来源边原子提交后才继续；不能越过 Gate，也不能把后台任务提交当作执行完成。
6. 完整序列的执行 ID 必须来自调度器、互不重复且顺序正确，真实失败保留终态结果。反馈另行检查；待结算、拒绝、中断、部分或未知执行保持 Unknown，相同参数不能借用另一次执行回执。
7. 反例追加 `needs_revision`。来源可提出新定义，但验证重置、历史 Uses/反馈不丢失，下一位消费者重新检查前提。
8. 重启在原有 Run Lock 下补全记忆结算，不重放操作。检查或存储失败在 `AgentResult.Cognition` 和恢复事件中单列。

## 三种压缩，三种权限

- **上下文筛选/压缩：**现有预算、Notes 和 Recall 生成有限请求视图，不改长期事实或证据。
- **经历摘要：**结构化 Experience 或宿主 `abstraction` 指向来源、前提版本；不是任意自然语言摘要已经正确的证明。
- **语义归并：**Governor 可归档等价别名，保存 `Memory.Canonical` 精确版本。要求所有者、范围、类型、断言、正文、来源/证据、依赖和有效时间一致。新绑定要求规范目标当前有效且同批不变；通用写入不能改别名。目标后来变化不阻止保留历史绑定的撤销，别名历史不删除。

不同事实、反例和有效区间不会被压平。更广解释需要新候选、新来源和新检查；不宣称自动通用泛化。

## 频率、最近使用、结果、证据分开

`Engine.CognitiveMemory(readerID, nodeID)` 只返回当前读者自己的统计。

| 信号 | 实际含义 | 不能说明什么 |
|---|---|---|
| `Access.Count` / `LastAccess` | `cognition_access` 中 `recall_experiences` 工具实际召回次数/时间；宿主直接只读不计数 | 重复查看不是独立使用或验证。 |
| `Outcomes.Adoptions` | 可见的唯一采纳记录数 | 采纳不代表执行过。 |
| success/failure/unknown/unconfirmed | 从不可变反馈计算 | 结果匹配不证明经验造成了收益。 |
| 模型置信度 | 可选的提案判断 | 不能提高证据等级或跳过检查。 |
| importance/retention | 宿主保留策略 | 重要信息也可能未知或错误。 |
| Evidence/applicability | 获准结果加当前来源、时间和范围 | 相似度、频率和新旧不能制造证据。 |
| `Utility` | `causal_benefit_unmeasured` | 没有虚构收益分或综合认知分。 |

Thread Recall 原有 30 天时间权重只影响排名，不是 TTL。每次反馈保存在原生版本中，不用可变总分代替。

## 保留、归档、撤销与恢复

- `MaintainCognitiveMemory(owner, capacity)` 只管理当前所有者集合。仅归档已 stale/dormant、未受保护、无引用的记录，优先较低重要性，每个事务最多 512 条。
- 保护对象：task/negative、失败或冲突证据、失败来源/负向预期经验、反例反馈、`needs_revision`、safety/counterexample 标记、importance≥0.8。容量维护同时保护依赖和图引用。
- **归档：**退出活跃使用、保留历史。通用 Node 更新也不能在归档时顺便去掉保护标记绕过规则。
- **恢复：**检查来源、依赖和有效时间，不产生验证证据。已撤销/失效身份不能复活；修正内容使用新身份。
- **撤销：**追加不可变失效版本；来源撤销复用 Fence 图，依赖内容不能继续使用。
- **隐私删除：**复用停止、Fence、安全清理、数据库重建与 WAL 恢复，清除相关版本、应用回执和访问统计。它不是腾空间捷径，Restore 不能撤销隐私删除。

若剩余内容都是活跃或受保护信息，返回 `Pressure=true`，不会为了数量目标删除罕见安全知识。冷热层仅逻辑元数据，不是物理分库。

## 上限与限制

Node 64 KiB；来源最多 8、依赖最多 16、依赖深度最多 32。评估最多 16 条，覆盖不足明确标记；应用最多 8 个操作，一条经验最多 8 个 Uses，字节上限可能更早达到。这些情况明确拒绝，不静默丢证据。

大型 Experience 集合与整图 Governor 仍需扫描选择域；没有引入 ANN/Embedding 数据库或自动破坏性 GC。来源推进可能使旧经验失效，需要真实新经历重新提取。隐私只覆盖 Core 受管状态，不覆盖外部备份或物理磁盘取证擦除；长期学习收益尚未测量。
