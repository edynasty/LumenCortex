# Go Experience validation contract

Unmerged Go completion candidate, 2026-11-13. The ordinary Agent and host paths use the same contract. Current source-bound results are in the [completion report](../reports/cognitive-core-final-completion-2026-11-13.md); historical checkpoints below keep their original scope. No paid model or real-task quality experiment was run.

## Public API

- `ExtractExperience(ctx, originID, ExperienceExtraction{ScopeKind, Proposal, Valid})`: requires an actual completed/failed Go Run and its source version. Framework reads origin run/task/workflow, actual execution/check locators and bounded workspace file hashes; stores an unverified candidate. Identical source/scope/definition/time extraction is idempotent.
- `ParseExperienceProposal`: strict typed JSON only. No status, check ID, evidence, source identity, scope or reasoning fields accepted from extractor output. Known secrets, credential-key assertions and private/absolute paths are rejected, not masked into memory.
- `ValidateExperience(ctx, originID, id, expectedVersion)`: exact approved assertions select checks. All conditions and outcome share one closed evaluator episode, so a check changing workspace state cannot leave earlier PASS results usable in a mixed-state promotion. Missing authority stays needs_evidence; a qualified mismatch is rejected. A failed origin cannot become an expected-success strategy; a reproduced negative outcome can validate a warning.
- `RecallExperiences(ctx, readerID, pattern, limit)`: read-only bounded task-token retrieval using the existing tokenizer; returns locators, not a strategy or truth claim. Scope/source/consumer fences and origin source/citation/time apply before selection. Matching counterexample warnings take priority. The ordinary `recall_experiences` tool separately records reader-local access and actual exposure; host diagnostics do not. Neither path grants successful-use credit. Retrieval quality beyond the deterministic scenarios remains unmeasured.
- `ReadExperience` and ordinary `ReadCognitiveNode`: historical definition and origin validation, filtered by current audience and revocation; raw `Uses` contains only the named reader's own adoption/feedback. Origin, unrelated and empty readers receive no consumer Uses. The same projection applies to mutation responses and duplicate extraction/feedback. Internal transitions retain the complete history. Historical validated state is not permission to reuse.
- `AdoptExperience(ctx, consumerID, id, expectedVersion)`: another session only, fresh consumer conditions, approval/fence/source/CAS check at commit. Commit adoption and provenance before returning strategy. Ordinary `apply_experience` explicitly matches the original complete action sequence and dispatches through normal tool authority; adoption alone grants no execution or success claim.
- `RecordExperienceFeedback(ctx, consumerID, id, adoptionID)`: requires a later terminal consumer run and its complete settled application receipt. It records success/failure/unknown once from the exact outcome check that the application ran when its last action had settled; it runs no check itself, whenever it is called. A real tool failure is observed use and may establish a counterexample or confirm a negative procedure; denied/interrupted/partial/unknown applications remain unknown. A failed task never becomes a successful task because its outcome check matched.
- `ReviseExperience(ctx, originID, id, expectedVersion, proposal)`: new definition, original source/trace and all prior uses preserved, validation reset; independent revalidation required. New source/citations require extraction from a new terminal run rather than rewriting the original.

## Existing authorities reused

Existing `knowledge` Scope/Times/SourceRef/Assertion/Evidence, native graph revisions, Session/Task State/Workflow snapshots, evaluator closed episodes, check approvals, run locks, `writeTx`, `derived_origins` and privacy fences remain authoritative. Migration 0017 adds bounded application/proposal/decision/access records in the same database after native graph 0016. Ordinary graph proposal APIs still reject Experience payloads.

The record's content owner is a dedicated internal maintenance session created atomically with the first node. Original and adopter lineage reaches it; deleting an origin or consumer fences all reads immediately and the existing bounded maintenance purge removes all revisions. Original user transcript is never replaced by an experience summary. User-owned scope and source privacy dominate retention.

## Boundedness and confidence

At most 3 conditions, 8 strategy steps, 4 cited files, 16 trace executions, 8 trace checks, 8 adoption records per Experience and 64 KiB per stored revision. Exhaustion refuses a write; no hidden retry loop. Historical definitions/revisions remain until explicit privacy erasure. Token-based selected-domain retrieval and finite use history do not establish unlimited scale or general task transfer.

`conditional` means current host checks qualified a conditional proposal. `contested` records a consumer counterexample. Usage/success/failure/unconfirmed counts derive from unique adoption records visible to this reader, not project-wide totals. Neither a retrieved strategy nor a matching outcome proves the strategy caused success. Reports separate Mechanism Correctness, Retrieval Quality and Real-world Task Improvement.

## Required scenario proof

Successful/failed origins; missing/wrong evidence; mismatch refusal; similar task matched by exact pattern plus independent conditions; separate A/B tool execution; failure/history; definition revision/revalidation; scope; privacy; idempotency; restart. Raw first failures and corrected checks are preserved. No Node test result is Go evidence.
